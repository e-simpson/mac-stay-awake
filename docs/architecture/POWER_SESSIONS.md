# Power sessions

The user app owns UI and built-in display brightness; the authenticated root helper owns persistent power settings. The existing native session/renewal/limit paths remain the only orchestration. Codex observation is not implemented.

`LidSession` enables an owned SleepDisabled flag only after its no-follow ownership marker is durable. Root `ClosedLidPower` captures supported original energy settings per battery/AC source in a private, atomically replaced, synced journal before writing. Helper status/renewal checks read real lid state and restore energy settings when opened, paused, expired, or ended. Failed activation rolls back.

End/cleanup attempts Low Power restoration before clearing owned sleep prevention, but clears that sleep override even if energy restoration fails. The energy journal remains for retry after wake. A valid ownership marker is required before clearing sleep; unsafe markers cannot clear a foreign flag. File and containing directory are synced on both new marker creation and retry. All power writes are serialized and read back. Timed-out children are terminated/reaped before another operation can proceed.

The user app persists original brightness before zeroing, tracks the current lid state, samples valid open-lid brightness, and retries display recovery on its existing check loop. It preserves observable external changes. Offline panels defer recovery. Required enabled-feature failures abort the session. Disabled optional overrides retain/retry their recovery and report failures while keep-awake remains active. Normal/Quit requests wait for serialized activation, renewal, status, and cleanup operations. Pending Normal requests are consumed before releasing the busy state, so stale replies cannot affect a newer session. A failed start is reconciled even when its timeout makes the helper outcome uncertain. Failed power recovery remains visible alongside any timer/safety stop reason and brightness failure; repeated identical errors do not grow the message. Brightness writes require readback within 0.005 before claiming success or clearing a saved original.

The bundle/helper IDs are `dev.personal.MacStayAwake` and `.helper`. Contributors must configure their own Developer ID Application identity and Team ID using `SIGNING.md`. The default unconfigured team deliberately prevents production packaging. Both XPC directions retain strict Developer ID/bundle/Team requirements. Preview builds compile out helper registration and disable display assertions; no unsigned trust bypass is supported.

The package targets macOS 13 or later. Physical compatibility and recovery acceptance across hardware and OS versions remain incomplete; no cross-version or physical-hardware claim follows from unit tests or inert previews.

Quit is a serialized recovery operation, including while Normal is selected. A user-defaults ownership hint is persisted before uncertain helper start/cleanup RPCs and cleared only on acknowledgement; the protected helper journal remains authoritative. Termination retries automatically every five seconds until display and power recovery succeed, then acknowledges AppKit termination. A quit latch rejects new manual/scheduled activation while recovery is pending. Forced process termination can bypass this flow.

Daily alarms use a validated maximum-16 array of local minutes, introduced in protocol 15. Legacy single-alarm preferences migrate on edit. One serialized synchronization loop coalesces changes and retains confirmed OS events until success. The helper keeps the next two owned occurrences per enabled time, deduplicates DST collisions, preserves already-owned imminent enabled events, and avoids cancelling the prior schedule after failed additions. Events belonging to other apps are never cancelled. An hourly app timer replenishes the horizon; quitting leaves queued alarms intact.


Selecting a duration explicitly resets the active countdown, even for the same choice; Infinite removes the timer. Protocol 17 resets only an active session’s timer and monotonic origin, preserving its lease and power state. Expired sessions cannot be restarted by changing the duration. Other settings retain the original countdown. In Normal, choosing a duration only saves the next session’s setting.

Mute applies to the default audio output and tracks it by its stable Core Audio device UID. The display-off option also dims the built-in keyboard backlight through macOS's private CoreBrightness interface when available. Each original value is saved before it is changed and restored on open, stop, quit, or the next launch after interruption; observable external changes are preserved. Saved mute settings for confirmed-disconnected audio outputs are discarded, so they do not block quitting or get applied to another output. Read, write, and persistence failures for connected devices still keep recovery pending. Unsupported controls report an error rather than inventing an original value.

## Operating limits

Brightness zero does not guarantee that the display panel is physically powered off. Brightness uses private DisplayServices APIs and unavailable panels defer restoration. Low Power Mode can reduce performance. Thermal-pressure protection does not guarantee safe operation in an enclosed bag. Legacy energy settings are refused when their original state cannot be restored safely. Avoid competing sleep-override utilities.

App watching estimates CPU work in launched process groups. System load, input, and other apps' keep-awake requests also affect idle detection. It does not observe Codex thread state, and model-response waits can look idle. Watching does not automatically start or restart Stay Awake and has no gating effect while Sleep when idle is disabled.

Setting events are emitted by the setting owners after observed readback, distinguishing verified changes, values already at target, preserved external changes, and pending/failed operations. Helper delivery is bounded and best effort: a lost reply, overflow, or process exit can lose entries. Missing entries do not prove that no change happened. Lifecycle event retrieval runs outside required recovery; explicit Log refresh can await it. Protocol 16 carries the separate setting-event stream without changing idle-event semantics.
